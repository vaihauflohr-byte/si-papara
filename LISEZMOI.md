# SI Papara — site d'entraînement, de mémorisation et de suivi

Site statique (GitHub Pages) + base Supabase (gratuite).
Aucun serveur à maintenir, rien ne dépend de Claude.

## Ce que fait le site

| Élève | Prof (`prof.html`) |
|---|---|
| Se connecte avec **classe + identifiant + code à 4 chiffres** (le professeur, lui, peut tout voir sans compte élève : « Aperçu élève ») | Voit **chaque entraînement** de chaque élève, question par question (réponse donnée, réponse attendue, points, nombre d'essais) |
| S'entraîne par séries de 10 questions tirées dans de grandes banques (données aléatoires) : **il part de 20 points, chaque erreur retire 2 points** (un calcul raté au 1er essai coûte déjà 2 points) → note /20 + appréciation (Maîtrisé ≥ 16, En cours 12–16, Fragile 8–12, À retravailler < 8) |
| Page « Mes compétences » : sa moyenne /20 par compétence du programme de SI | Onglet « Compétences » : grille élèves × compétences (moyennes /20), et bloc compétences dans la fiche de chaque élève | Suit la lecture quotidienne des fiches (calendrier sur 60 jours, assiduité par fiche) |
| À la fin : **mini-fiches** proposées → ajoutées à son programme de **60 jours** | Voit qui a fait la **révision de la semaine** (et sur les 4 dernières semaines) |
| **Fiches du jour** : recto (question) → il répond de tête → verso → « Je savais / À revoir » | Repère les points faibles (erreurs regroupées par fiche) |
| **Révision hebdomadaire** : QCM sur toutes ses fiches, en priorité celles « à revoir » | Crée les comptes élèves, imprime les codes, réinitialise un code, exporte en CSV |
| Hors ligne : résultats gardés puis envoyés au retour du réseau | |
| **Appli** : installe le site sur l'écran d'accueil de son téléphone (icône au logo du lycée) ; les pages déjà ouvertes marchent sans réseau | Onglet **« Signalements »** : les questions que les élèves croient fausses, telles qu'ils les ont eues (valeurs, figure), avec sa réponse et la réponse attendue |
| **« Signaler une erreur »** sous chaque question des séries, du sujet blanc, d'Observe et de « Vérifie » ; il voit ensuite si son signalement est retenu | « Erreur confirmée », « Pas d'erreur », « Valider sa série » (la série lui est comptée 16/20 à la date du signalement) |
| **DS blancs** (Terminale SI, `entrainements/ds-blanc.html`) : un sujet du même type que le prochain DS (mêmes notions, même format, autre système), **question par question** (correction après chaque réponse), en 1 h chrono ou sans chrono ; les résultats chiffrés et le DR sont vérifiés par le site, les justifications et conclusions par une IA à partir du corrigé (sinon auto-évaluées) ; bilan par question et par notion ; nouvelles valeurs à chaque essai | Note /20 de chaque essai et détail question par question (réponse, rédaction, points du barème) dans le suivi ; colonne **« DS blanc »** dans l'onglet Bac SI et dans l'export CSV ; « q/q » pour un essai fait question par question |

Au bout de 60 jours de cycle, une fiche passe « ancrée » : elle quitte la lecture quotidienne mais reste dans la révision hebdo.

## 1. Tester tout de suite (mode démo)

Ouvre `index.html` dans un navigateur : sans configuration, le site tourne en **mode démo** (données dans le navigateur).
Élève : n'importe quelle classe, identifiant `demo`, code `1234`. Prof : `prof.html`, mot de passe `demo`.

## 2. Créer la base Supabase (≈ 10 min, une seule fois)

1. Crée un compte sur supabase.com → **New project** (nom `si-papara`, mot de passe de base à garder, région **West US (North California)** : le câble de Tahiti passe par Hawaï et les États-Unis).
2. **SQL Editor → New query** : colle tout `supabase/schema.sql` → **Run**.
3. **Authentication → Users → Add user** : ton e-mail + un mot de passe (coche « Auto confirm »).
4. De retour dans le SQL Editor, exécute (avec ton e-mail) :
   ```sql
   insert into public.profs (user_id, nom) select id, 'Olivier' from auth.users where email = 'TON_EMAIL';
   ```
5. **Authentication → Sign In / Providers** : désactive « Allow new users to sign up » (seuls les comptes que tu crées pourront se connecter côté prof).
6. **Project Settings → Data API** : copie l'URL du projet ; **Project Settings → API Keys** : copie la clé **publishable** (`sb_publishable_…`) — ou, selon l'écran, la clé **anon public** (onglet *Legacy API keys*). Colle les deux dans `config.js`.

La clé *publishable/anon* peut être publique : les élèves ne passent que par des fonctions contrôlées par jeton, aucune table n'est lisible directement. Ne mets **jamais** la clé *secret* / *service_role* dans le site.

> Plan gratuit Supabase : un projet sans activité pendant 7 jours est mis en pause (il se réactive depuis le tableau de bord). En période scolaire, l'activité des élèves suffit ; pense à le relancer à la rentrée.

## 3. Mettre en ligne sur GitHub Pages

Dans l'organisation `si-papara`, crée le dépôt **`si-papara.github.io`**, dépose tout le contenu de ce dossier à la racine, puis **Settings → Pages → Deploy from branch → main / root**.
Le site est alors sur `https://si-papara.github.io/` et l'espace prof sur `https://si-papara.github.io/prof.html`.
Tu peux mettre le lien du site dans l'ENT (nati.pf) comme lien externe.

## 4. Créer les comptes élèves

`prof.html` → onglet **Élèves et codes** → choisis la classe → colle un identifiant par ligne (ex. `teva.m`) → **Créer et générer les codes** → **Imprimer** → découpe les coupons.
Les codes sont chiffrés en base : ils ne sont visibles qu'à la création. Code perdu → « Nouveau code ».
5 codes faux d'affilée bloquent le compte 10 minutes.
Fin d'année : « Désactiver » plutôt que « Supprimer » (supprimer efface tout l'historique).

## Aperçu professeur : tester une filière sans compte élève

Pour voir le site exactement comme un élève de **n'importe quelle filière** (2de SI, 1re SI, Tle SI, BTS 1/2 STI et ADM), sans créer de compte élève :

- `prof.html` → onglet **Aperçu élève** → « Ouvrir l'aperçu » sur la filière voulue (ou lien « Aperçu élève » en haut de l'espace prof) ;
- ou, une fois connecté à l'espace prof dans ce navigateur, la page d'accueil du site affiche un bloc **Mode professeur** avec les 7 filières ; l'adresse `index.html#/apercu/BTS2-STI` (`2SI`, `1SI`, `TSI`, `BTS1-STI`, `BTS1-ADM`, `BTS2-STI`, `BTS2-ADM`) y mène directement.

Dans l'aperçu, tout fonctionne comme pour un élève : tableau de bord de la filière (prochain DS en Terminale, tuile E4 en BTS 2), séries, fiches du jour, révision de la semaine, fiches de révision, pages `bac-si.html` et `bts-e4.html`. **Rien n'est transmis** : les essais sont gardés dans une base locale au navigateur (`sip_apercu_db`) et n'apparaissent ni dans le suivi ni dans les grilles. Un bandeau bleu en haut permet de **changer de filière**, d'**effacer ses essais** ou de **quitter l'aperçu**.

Sécurité : l'aperçu ne s'ouvre que si le navigateur a une session professeur valide (compte Supabase inscrit dans `profs`) ; un élève qui tape l'adresse voit « Aperçu réservé au professeur ». Se déconnecter de l'espace prof ferme l'aperçu. Si un élève était connecté sur l'appareil, sa session revient quand on quitte l'aperçu, et ses résultats en attente (hors ligne) ne sont jamais mélangés à ceux de l'aperçu. En mode démo (site non configuré), l'aperçu est ouvert à tous.

## Bac SI — séries notées (Terminale)

`entrainements/bac-si.html` = l'entraînement « Bac SI par notions » relié au site : bandeau de connexion en haut, et chaque **série**, **parcours** et **révision du jour** part dans le suivi (module `bac-<notion>`, détail question par question).
Le tableau de bord d'un élève de Terminale est tourné vers l'écrit : bandeau du prochain DS (notions à valider), accès direct à la révision du jour, au parcours « faiblesses », au **sujet blanc** (20 questions, 40 min, corrigé à la fin) et aux fiches **« Réussir l'écrit »** (`contenu/methode-bac.js`, page `#/methode`), puis la liste des 41 notions avec leur état ; chaque notion ouvre directement sa série (`entrainements/bac-si.html#n=<notion>`). Les anciens modules de cours restent disponibles, repliés en bas (« Questions de cours rapides »).

**Préparation du DS en étapes (12 octobre)** : le bandeau « Prochain DS » du tableau de bord n'est plus « fiche puis série par notion » mais un parcours **progressif**, verrouillé dans l'ordre : **étape 1 Les briques** (questions de niveau 1 : reconnaître, lire, nommer), **étape 2 Les calculs** (niveau 2), **étape 3 Les chaînes** (niveau 3 : résoudre et conclure comme au DS), puis le **DS blanc** quand il existe. Chaque étape est notée comme une série (20, −2 par erreur) et, validée à 16/20, ouvre la suivante ; essais illimités, autres valeurs à chaque fois, jusqu'à 6 h le jour du DS. Les fiches des notions sont proposées au-dessus des étapes. Le contenu de chaque étape est décrit dans **`contenu/prep-ds.js`** (modifiable sur GitHub sans rien regénérer) : par DS, des blocs `{ k: réservoir, l: niveau, g: [générateurs], n: combien }` qui ne retiennent que les générateurs proches du DS (DS 02 et DS 03 sont décrits ; un DS absent du fichier a quand même ses trois étapes, tirées dans tous les générateurs de ses notions). Résultats transmis sous les modules `prep-<ds>-<étape>` (ex. `prep-ds02-1`) ; les trois étapes validées à temps valident aussi les notions du DS (« ✓ prép. » dans la grille). `prof.html` → Bac SI : colonne **Préparation** par DS (E1 E2 E3, puis DSb), reprise dans le CSV. Dans `entrainements/bac-si.html`, carte « Préparer le DS » en tête, vue `#prep=ds02`, lancement direct `#prep=ds02:2` (`:ok` quand le site a déjà validé les étapes précédentes).

**DS blanc question par question (12 octobre, soir)** : en plus de « en conditions de DS » (1 h chrono) et « à mon rythme », le DS blanc se fait **une question à la fois** (conseillé pour commencer ; une fois un essai fait ainsi, « en conditions de DS » devient le conseil). L'élève répond, appuie sur **Vérifier** : sa réponse est figée et la correction s'affiche aussitôt (verdict de chaque case avec les erreurs de signe et d'unité, bilan des actions corrigé, son texte, le corrigé, le barème avec les cases d'auto-évaluation, les erreurs fréquentes, « Signaler une erreur »), puis **Question suivante**. Pastilles A.1 … B.4 colorées (juste, en partie, faux), score courant, reprise là où il s'était arrêté ; les documents (présentation, hypothèses de la partie) sont repliés au-dessus de la question et s'ouvrent d'eux-mêmes quand la question cite leurs figures ou une exigence. À la fin (ou « Terminer »), la correction complète commence par un **bilan** : points par question (un clic mène à la question) et par notion, avec « Revoir la fiche » sous 80 %. Même module `dsb-ds02`, titre terminé par « (question par question) » ; dans `prof.html` → Bac SI, la pastille **q/q** (meilleure note question par question) est à côté de **DSb** (meilleure note en conditions de DS ou à son rythme). Le bilan par question et par notion s'affiche aussi après un essai chronométré. Sur téléphone, le bilan des actions corrigé s'affiche en cartes (une par action).

**DS passés (13 octobre)** : après la date d'un DS, le bandeau « Prochain DS » passe au suivant ; juste dessous, une carte **« DS passé · revois tes erreurs »** garde l'accès au DS qui vient d'avoir lieu : son DS blanc (question par question), sa préparation en 3 étapes (toujours ouverte, elle ne compte plus pour la validation : dans `entrainements/bac-si.html#prep=ds02`, titre « Revoir le DS 02 ») et les fiches de ses notions. Les DS plus anciens sont repliés dans « Les DS d'avant ».

**Rédactions vérifiées par l'IA (12 octobre, nuit)** : dans les DS blancs, les justifications et conclusions rédigées sont lues par une IA (Claude Haiku 5.5, par l'API) qui les compare au corrigé et au barème. Pour chaque élément rédigé du barème : **présent** (tous les points), **en partie** (la moitié) ou **absent** (0), avec une phrase pour l'élève, puis un conseil. Question par question : juste après « Vérifier » ; en conditions de DS et à son rythme : à l'ouverture de la correction (deux à la fois, « Envoyer ma note » attend la fin). Les verdicts sont gardés dans l'essai, jamais redemandés. Sans l'IA (élève non connecté ou désactivé, pas de réseau, quota du jour atteint, fonction pas encore installée) : auto-évaluation comme avant, avec un message et « Réessayer avec l'IA » ; si la fonction ne répond pas du tout, le site n'insiste plus pendant 5 minutes (cases à cocher, sans message à chaque question). Un élément que l'IA n'a pas jugé reste à cocher par l'élève (jamais compté absent d'office). Les élèves voient « Rédaction vérifiée par une IA (Claude) à partir du corrigé : elle peut se tromper » ; un verdict contesté arrive dans **Signalements** avec le texte de l'élève et le verdict de l'IA. Dans le détail d'un essai (prof.html) : « vérifié par l'IA ✓◐✗ : ce qui manque ».

- **Chemin** : site → fonction Supabase **`corriger`** (`supabase/functions/corriger/index.ts`) → API Claude. La clé de l'API reste dans les secrets de Supabase (`ANTHROPIC_API_KEY`) : jamais dans le site ni sur GitHub. Ne partent vers Claude que l'énoncé, le corrigé, les éléments du barème et le texte de l'élève, sans nom ni identifiant.
- **Contrôles** : un élève est reconnu par son jeton de session (et doit être actif : le désactiver dans l'espace prof coupe aussi l'IA), et ses vérifications sont comptées (table `ia_appels`, fonction `ia_autoriser`, fichier **`supabase/ia.sql`**) : 80 par jour et par élève au plus (un DS blanc complet en demande 8). Le professeur en aperçu est reconnu par sa session de l'espace prof (`is_prof`), sans quota.
- **Coût** : environ 0,0004 $ par réponse vérifiée avec Haiku 5.5, soit quelques centimes pour un DS blanc de toute la classe. Fixe une limite de dépense mensuelle dans la Console Claude.
- **Réglages** (secrets de la fonction, facultatifs) : `IA_MODELE` (par défaut `claude-sonnet-5-5` depuis le 17 novembre ; `claude-haiku-5-5` coûte vingt fois moins mais jugeait mal les flashs), `IA_EFFORT` (`medium`), `IA_MODELE_SECOURS` (`claude-haiku-5-5`, si le modèle demandé n'existe plus), `IA_QUOTA_JOUR` (80), `IA_ORIGINES` (adresses du site autorisées ; par défaut `https://si.ka-ilei.com,https://vaihauflohr-byte.github.io`). Pour couper la vérification sans rien supprimer : `ia: false` dans `config.js`.
- **Installation (une fois)** : 1. crée une clé API dans la Console Claude (platform.claude.com) ; 2. Supabase > SQL Editor > New query : colle `supabase/ia.sql`, Run ; 3. Supabase > Edge Functions > Secrets : `ANTHROPIC_API_KEY` = ta clé ; 4. Edge Functions > Deploy a new function > Via Editor : nom `corriger`, colle `supabase/functions/corriger/index.ts`, Deploy function, puis désactive la vérification du JWT dans les réglages de la fonction (la fonction contrôle elle-même qui l'appelle) ; 5. dépose le site ; 6. teste avec un **compte élève** (par exemple un élève « Test » créé dans l'espace prof : l'aperçu passe par ta session de professeur et ne montrerait pas une vérification du JWT restée active) : DS blanc > Question par question, rédige une justification, Vérifier → « Rédaction vérifiée par l'IA ». En cas de souci : Edge Functions > corriger > Logs. La fonction s'arrête d'elle-même au bout de 28 s ; textes bornés (énoncé 2 500 caractères, corrigé 4 000, réponse 2 000, 8 éléments) ; les signes < et > du texte de l'élève sont neutralisés.

**Règle de notation** : une notion est **validée** si l'élève obtient **16/20** à l'une de ses séries **avant l'échéance = le jour de son DS, 6 h (heure de Tahiti)**, ou si les trois étapes de la préparation de son DS sont validées à temps. C'est l'heure de **réception par le serveur** (`recu_le`) qui compte : un résultat resté hors ligne et envoyé après l'échéance est « hors délai ».
`prof.html` → onglet **Bac SI** : grille élèves × notions (meilleure note, nombre d'essais, ✓), « Validées à temps x / y » sur les échéances passées, note /10, révision du jour et parcours sur 7 jours, dernier et meilleur sujet blanc ; **Exporter cette grille** → CSV pour Pronote. Clic sur un élève → toutes ses séries, question par question.

Elle n'est pas imprimée (la fiche reste sur une page) et respecte le réglage « réduire les animations » du téléphone. Badge « animation » dans l'index des fiches.

Le moteur `A` (= `SIP.ANIM`, en tête du fichier) fournit le cadre figure + panneau (`A.cadre`), le dessin SVG (`A.svg`, `A.fleche`, `A.texte`…), les contrôles (`A.predire`, `A.curseur`, `A.choix`, `A.bouton`), les mesures (`A.mesures`, nombres à 3 chiffres significatifs avec `A.nf3`) et le mouvement (`A.boucle`). **« Observe et réponds »** (`assets/observe.js`, `contenu/observe-bac.js`) : dans la fiche, au-dessus de l'animation, un mode où le mécanisme bouge seul, sans ses traces ni ses vecteurs, et où l'élève répond à une série de questions sur ce qu'il voit (mouvement de la pièce, trajectoire d'un point, vitesses) : correction immédiate, note qui part de 20 et perd 2 points par erreur, bilan transmis au professeur (module `observe-<notion>`, visible dans le détail de l'élève). La série règle elle-même l'animation (mécanisme, curseurs, boutons) avant chaque question, par le registre des missions, et cache les groupes de la figure marqués `data-role` (traces, vitesses). Un bouton « Manipuler » rend les curseurs et les missions. Les animations cachent leurs valeurs chiffrées pendant la série (groupes `data-role` valeurs, vecteurs, moment). Un bouton « Observe et réponds » en haut de la fiche ouvre directement le volet ; badge vert « observe » dans l'index des fiches. Ajouter une série = une entrée `SIP.OBSERVE_BAC["<id>"]`, format en tête de `assets/observe.js`.

**Fiches interactives : « Vérifie que tu as compris »** (`assets/verif.js`, `contenu/verif-bac.js`) : dans chaque fiche, après chaque partie, 1 ou 2 questions (QCM, vrai/faux, calcul à valeurs tirées au hasard, étapes à remettre dans l'ordre) avec correction immédiate et lien « Relis… » ; en fin de fiche, le bilan « Ai-je compris ? » (note /20 au premier essai, parties à relire). La note est transmise au professeur si l'élève est connecté (type « externe », module `fiche-<notion>`, sans modifier la base) : ligne « fiche » sous chaque notion dans l'onglet Bac SI de `prof.html`, détail question par question dans la fiche de l'élève ; côté élève, le bouton « Fiche » devient « Fiche ✓ » dès 16/20. Rien n'est imprimé. 175 questions pour les 22 fiches ; format décrit en tête de `assets/verif.js`.

**Correction des flashs par l'IA, plus juste (17 novembre)** : le flash du 17 novembre a montré une IA incohérente (« moteur = convertir » noté 2/2 chez un élève et 1,5/2 chez un autre pour la même réponse ; « direction : à gauche, sens : vers le point A » noté 1,5/2). Quatre changements :
- **Modèle** : la fonction `corriger` utilise **Claude Sonnet** par défaut (au lieu de Haiku, en effort bas), en effort moyen. Avant chaque verdict, l'IA cite ce que l'élève a écrit sur l'élément (« extrait »).
- **Précisions pour le correcteur** : chaque élément du barème des flashs (`contenu/flashs-banque.js`, `contenu/flashs.js`) a un champ `aide`, envoyé à l'IA seulement : formulations acceptées, réponses fausses fréquentes, cas « en partie » (par exemple : « convertir » suffit, sans les formes d'énergie ; « démarrer » est faux ; direction juste et sens faux : en partie). Ce qui est entre parenthèses dans un élément explique la réponse à l'élève : ce n'est plus exigé.
- **Règles de correction des flashs** (`REGLES_IA` dans `assets/flash.js`, envoyées avec chaque réponse) : la consigne des élèves est « écris ton calcul et ton résultat avec l'unité », donc un résultat juste sans calcul, ou sans unité, compte la moitié de l'élément ; une conclusion sans la comparaison qui la justifie aussi ; un mot ou une valeur à lire (une fonction, un point, un nombre de tours) suffit sans justification. Une pièce est une liste de fonctions, comme dans Onshape : des esquisses (contours fermés tracés à la Ligne, au Rectangle, au Cercle, cotés) et des extrusions (Nouveau, Ajouter, Supprimer ; Borgne avec une profondeur, ou À travers tout). L'arbre les liste, on clique pour les rouvrir, la croix les supprime. Le moteur (`moteur`, `maillage`) découpe la pièce en bandes où la matière se calcule exactement : contours qui se chevauchent, trous, poches, épaisseurs différentes. Le planeur de départ est écrit ainsi : fuselage = Esquisse 1 + Extrusion 1 (corps, 5 mm), Esquisse 2 + Extrusion 2 (dérive, Ajouter 1 mm), Esquisse 3 + Extrusion 3 (deux fentes et trou du lest, Supprimer à travers tout) ; aile et stabilisateur = demi-esquisse + extrusion + symétrie automatique. Tant que l'élève n'a pas touché au fuselage, ses fentes suivent l'aile ; ensuite elles sont à lui, le contrôle vérifie qu'elles sont à la bonne place et à la bonne taille (coordonnées des coins données), et le bouton « Replacer les fentes et le trou du lest » les refait. Pièce d'essai : trois défis (plaque 6,00 cm³, biseau 5,76 cm³, trou 5,70 cm³). Les pièces modifiées sont rangées dans `cao` de l'idée (onglet « Créer »), donc enregistrées avec le compte.

Atelier 3D, l'esquisse se comporte comme celle d'Onshape (23 novembre, soir). Dans `cao.js` :
- **Bleu / noir.** `definis(ct)` calcule, par élimination de Gauss sur les contraintes, quels points ne peuvent plus bouger. Un trait est noir seulement si ses deux bouts sont entièrement fixés ; sinon il reste bleu. La barre sous le dessin dit si l'esquisse est entièrement définie.
- **Origine et coïncidence.** Un point posé (ou lâché) sur l'origine y reste attaché (`ct.q` avec `co: 1`, symbole près du point). C'est ce qui permet de tout définir avec deux cotes pour un rectangle.
- **Cotes sur le dessin.** Outil Cote : on clique un trait, un cercle ou un arrondi ; la cote suit la souris, on clique pour la poser, on tape la valeur dans la boîte qui s'ouvre à cet endroit (`#a3-boite`), Entrée. Pour placer un point : clic sur le point, puis sur l'origine (ou un autre point du contour) ; souris au-dessus ou au-dessous = distance horizontale, à gauche ou à droite = distance verticale. Double-clic sur une cote : changer sa valeur. Glisser une cote : la déplacer. Suppr : la retirer.
- **Aimantation.** `accroche()` : sur un point connu (rond orange), dans l'alignement d'un point (pointillés), sinon sur la grille. Avec l'outil Ligne, un trait bien horizontal ou vertical reçoit sa contrainte (symbole près du trait) ; Maj l'empêche. La longueur et l'angle s'affichent près du pointeur.
- **Congé.** Un arrondi est gardé comme un rayon sur le coin (`ct.a`), pas comme une suite de points : il se dessine en vrai arc, garde sa cote « R » modifiable, et suit le coin quand on le déplace. `anneau(ct)` donne au moteur le contour avec ses arcs.
- **Souris.** Un point ou un trait se tire (le solveur `resoudre` déplace le reste pour tenir cotes et contraintes) ; le bord d'un cercle se tire pour changer son diamètre ; ce qui est entièrement défini ne bouge plus. Chaque trait a une zone de clic large et invisible (`.a3-sh`).
- **Boîte de l'esquisse** en haut à gauche, avec ✓ (valider) et ✕ (fermer sans garder les changements, annulable).
- **Raccourcis** : L ligne, G rectangle, C cercle, D cote, Maj+F congé, H / V contraintes, N normale à l'esquisse, F tout voir, Échap lâcher l'outil, Suppr ; hors esquisse : Maj+S esquisse, Maj+E extruder.
- **Hauteur de la vue** : `ratio()` ne dépend plus de la hauteur de l'arbre (la vue grandissait à chaque affichage et le dessin glissait sous la souris pendant les premiers clics) ; elle tient dans la fenêtre.
- **Plan de l'esquisse.** Comme dans Onshape, le bouton Esquisse demande d'abord le plan : l'arbre liste « Dessus », « Face », « Droite » ; la vue 3D montre les trois plans (toujours quand la pièce est vide), et un clic sur le bon plan, dans l'arbre ou dans la vue, ouvre l'esquisse. Un mauvais plan est refusé avec une explication (`choisirPlan`, `plans`).
- **Vue 3D.** Une esquisse validée mais pas encore extrudée reste visible, en bleu. Quand la boîte d'extrusion est ouverte, la pièce montrée est un aperçu en jaune, qui suit la profondeur tapée (`apercu`), et l'esquisse utilisée est en orange. En fermant une esquisse, on retrouve l'angle de vue d'avant.
- **Deux ordres possibles**, comme dans Onshape : Esquisse puis le plan, ou le plan (dans l'arbre ou dans la vue) puis Esquisse (`selPlan`).
- **Contrainte Fixe** (ancre) : le point ou le trait cliqué ne bouge plus (`fixer`, entrées `fx` de `ct.q`). Utile pour rendre noire une forme libre sans la coter partout.
- **Arc** (touche A) : on clique un trait du contour, il se courbe pour passer sous la souris, on clique pour le poser. L'arc est gardé comme une flèche sur le trait (`ct.b`, ou un rayon coté `ct.br`) ; `arcs(ct)` en donne le centre et le rayon, `arrondi(ct)` le découpe en petits traits pour le moteur. Sa cote « R » se change par double-clic ; l'arc se tire à la souris ; Suppr remet le trait droit. Refusé s'il fait se croiser le contour ou sortir du plan (`arcBon`). Un congé ne se pose pas sur un coin qui touche un arc.
- **Tirer à la souris.** Le point tiré suit exactement la souris (donc reste sur la grille) ; si une cote l'en empêche, il ne la suit qu'en hauteur ou qu'en largeur (`resoudre(ct, fixe, mou, axe)`) ; sinon il est bloqué. Pendant un tracé à la Ligne, Retour arrière enlève le dernier point.
- **Noms et raccourcis vérifiés** sur l'aide en français d'Onshape (page « Touches de raccourci et raccourcis clavier », lue le 23 novembre 2026) : L ligne, G rectangle par sommet, R rectangle à partir du centre, C cercle à partir du centre, A arc, D cote, Maj+F congé d'esquisse, H horizontal, V vertical, B parallèle, Maj+L perpendiculaire, E égal, Maj+J fixer, N vue normale, F tout voir, P plans, Maj+S esquisse, Maj+E extrusion.
- **Contraintes entre deux traits** d'un même contour : Parallèle, Perpendiculaire, Égal (`ct.r2`, fonction `lier`). On clique la contrainte puis les deux traits, ou un trait puis la contrainte puis l'autre trait. Le même symbole apparaît sur les deux traits.
- **Solveur** : `resoudre` est maintenant une méthode de Newton amortie (Levenberg-Marquardt) sur le système écrit par `systeme(ct)` (écarts et dérivées de chaque contrainte) ; la même matrice sert à `definis` pour le bleu / noir. Il déplace les points le moins possible, tombe juste (au centième), et dit « impossible » quand les contraintes se contredisent.
- **Cote tapée juste après le tracé**, comme dans Onshape : après un rectangle, une boîte attend la largeur, puis la hauteur ; après un cercle, le diamètre. On peut l'ignorer : continuer à cliquer, Échap ou une lettre de raccourci la referment.
- **Rectangle à partir du centre**, bouton « Plans » (touche P), aide-mémoire des gestes sous le texte d'introduction, contraintes en petits boutons pour que la barre tienne sur une ligne.
- **Esquisses entièrement définies, pour l'évaluation.** `Planeur3D.definition(d)` compte, par pièce, les esquisses dont tous les traits sont noirs. L'atelier l'affiche sous le tableau de l'assemblage, et la page du professeur dans la colonne « Esquisses définies » (F fuselage, A aile, S stabilisateur) : c'est le critère B1. L'aile et le stabilisateur de départ, quand ils sont rectangulaires, arrivent entièrement définis (origine, côtés droits, deux cotes) : on les modifie en changeant une cote, comme dans Onshape. Le fuselage de départ reste libre (bleu).
- **Cote d'angle.** Outil Cote, clic sur un trait puis sur un trait voisin : la boîte demande l'angle du coin, en degrés (`ct.an`, numéro du point → angle). Elle se dessine comme un petit arc dans le coin, se change par double-clic, se retire avec Suppr. Le solveur refuse une solution qui écraserait un trait à rien.
- **Défi 5, « tout en noir »**, sur la pièce d'essai : après le biseau et le trou, rendre les deux esquisses entièrement définies (contrainte Horizontal, cotes de longueur, cote de diamètre, deux cotes de position). C'est le critère de réussite des missions Onshape (« tous les traits noirs »). Il ne compte pas dans les lignes à cocher de l'onglet « Les étapes ».

Atelier 3D, courbes et prise en main (24 novembre) :
- **Courbes.** Un point du contour peut être « courbe » (`ct.l = {point: 1}`) : le contour ne passe plus par ce point, il est attiré par lui. La courbe part du milieu du trait d'avant, arrive au milieu du trait d'après, tangente aux deux (`douce()`, découpée en petits traits par `arrondi()`). Elle ne sort donc jamais du contour en traits droits et les longueurs cotées restent vraies : l'aile de départ avec ses deux coins de bout en courbe garde 45 × 200 mm. Ce n'est pas la spline d'Onshape, qui passe par ses points : choix fait pour qu'un coin de rectangle s'arrondisse sans gonfler ni sortir de la zone.
- Outil **Courbe** de la barre : points posés un à un comme la ligne, fermeture sur le premier point ; tous les points sont « courbe », sauf ceux posés contre le fuselage. Sur un point déjà tracé : **Courbe ici** / **Coin vif** (barre du bas, menu du clic droit), refusé contre le fuselage (la pièce n'entrerait plus dans sa fente). Les traits qui guident une courbe sont en pointillé et se sélectionnent, se cotent et se contraignent comme les autres. Pas de congé ni d'arc sur un point ou un trait de courbe.
- **Tracer d'un geste** à la souris : appuyer, tirer, lâcher (Ligne, Rectangle, Cercle, Courbe), en plus des deux clics.
- **Le prochain geste clignote** hors du défi guidé (`conseil()`) : Esquisse sur une pièce vide, le plan conseillé, Extruder quand une esquisse valable n'est pas extrudée, Valider quand l'esquisse ouverte est entièrement définie.
- **Barre d'esquisse « débutant »** par défaut : Sélection, Ligne, Rectangle, Cercle, Cote, Congé, puis Supprimer, Effacer, **Plus d'outils**, Valider (une seule rangée sur iPad). « Plus d'outils » ajoute rectangle centre, arc, courbe libre et contraintes ; le choix est gardé sur l'appareil (`localStorage.sip_cao_tous`). Les outils cachés restent accessibles par le clic droit et par les raccourcis (un raccourci d'outil caché déplie la barre) ; l'outil en cours est toujours affiché.
- **Un seul geste évident pour arrondir un coin : le congé.** Un coin choisi propose « Arrondir ce coin » (rayon tapé, comme dans Onshape). « Courbe ici » n'apparaît qu'avec « Plus d'outils ».
- **L'atelier prend toute la fenêtre** (largeur ≥ 900 px) : il sort de la colonne de texte (`large()`), vient se caler sous les onglets à l'ouverture (`placer()`), et sa hauteur tient dans la fenêtre (`ratio()` : hauteur de fenêtre − 314 px). Le bouton plein écran reste là pour cacher aussi les onglets.
- **Esquisse sur une face de la pièce**, comme dans Onshape. Une esquisse peut porter une hauteur `h` (mm au-dessus du plan de départ). Quand la pièce a déjà de la matière, Esquisse propose ses faces du dessus, en bleu dans la vue et dans l'arbre (`facesP()`, « Face de la pièce · à 5,4 mm ») ; le plan de départ reste possible. Moteur : Ajouter monte au-dessus de l'esquisse (`[h, h + profondeur]`), Supprimer creuse sous la face (`[h − profondeur, h]`), à travers tout traverse toute la pièce. Sans `h`, rien ne change (vérifié : mêmes volumes que l'ancien moteur sur 1 500 pièces au hasard et sur les planeurs de départ).
- **On voit le reste du dessin** : esquisse ouverte, la pièce reste bien visible derrière et les autres esquisses sont en pointillé gris ; une esquisse validée mais pas extrudée se voit même à travers la pièce.
- **Extrusion sans effet signalée** : si « Ajouter » ne change pas le volume (matière déjà dans la pièce), la boîte le dit en rouge et propose de dessiner sur une face.
- Demi-pièces : l'épaisseur qui entre dans la fente est celle mesurée contre le fuselage, plus l'épaisseur maximale (un relief sur l'aile n'épaissit plus son emplanture).
- **Une esquisse posée sur une face suit cette face** : elle garde la référence de l'extrusion qui a fait la face (`hr = [extrusion, 1 dessus | 0 fond de poche]`, résolue par `etages()`). Si on change la profondeur de la semelle, le bossage, le trou et la poche dessinés dessus montent ou descendent avec elle. Extrusion supprimée : l'esquisse garde sa dernière hauteur (`h`).
- **Hauteur de l'atelier constante** : l'arbre des fonctions défile dans sa colonne au lieu d'étirer l'atelier (il passait de 627 à 883 px sur le fuselage et poussait les onglets de pièces hors de l'écran) ; il défile tout seul jusqu'à la fonction ouverte.
- **Arêtes** : plus de faux traits verticaux sur les cylindres et les congés (`vif()`, `aigu()` dans `aretes()`).
- Pièce d'épreuve construite à la souris dans l'atelier (semelle en L cotée, deux congés, bossage rond, trou traversant, poche, relief en courbe libre), puis modifiée : c'est elle qui a fait apparaître les trois défauts ci-dessus.

- Fuselage rejoué à la souris et au clavier réel (tirer un point, ajouter un point, congé tapé, hauteur d'un point tapée, valider) : rien de cassé, contrôle vert.
- Vérifié sans navigateur : 2 000 contours au hasard (courbes, congés, arcs mélangés), volume du maillage égal au volume calculé, aucune courbe hors de la boîte de ses points.

## 5. Ajouter du contenu

Un fichier par groupe de séquences dans `contenu/` (ex. `1si-s3.js`, `tsi-s8.js`). Un module = un chapitre, avec `sequence` (regroupement à l'écran), `competences` (codes de `competences.js`), ses questions et ses mini-fiches :

```js
SIP.definirModule({
  id: "tsi-nouveau", niveaux: ["TSI"], sequence: "S14 · …", competences: ["A2", "M15"],
  titre: "…", description: "…", nbQuestions: 10,
  questions: [
    { type: "qcm", fiche: "tsi-nv-f1", enonce: "…", choix: ["bonne", "fausse", "fausse"], bonne: 0, explication: "…" },
    { fiche: "tsi-nv-f1", gen: (r) => { const U = r.pick([12, 24]), I = r.pas(0.5, 3, 0.5);
        return { enonce: `U = ${U} V, I = ${SIP.nb(I)} A. P ?`, reponse: U * I, unite: "W", tolerance: 2, explication: "…" }; } }
  ],
  fiches: [
    { id: "tsi-nv-f1", titre: "…", recto: "Question de rappel", verso: `<div class="formule">P = U·I</div><p>…</p>`,
      quiz: [{ enonce: "…", choix: ["bonne", "fausse"], bonne: 0 }] }   // 2 questions par fiche pour la révision hebdo
  ]
});
```

Autres types : `gen` peut renvoyer `{ type: "texte", reponses: ["1011", "0b1011"] }` (réponse courte) ou `{ type: "qcm", choix, bonne }` (QCM à données aléatoires) ; `absolu: 0.5` remplace la tolérance en % (entiers exacts, valeurs nulles).
Tolérance des calculs = écart relatif en valeur absolue |réponse − attendu| / attendu. Pour un nouveau fichier, ajoute sa ligne `<script src="contenu/….js">` dans `index.html` **et** `prof.html`.
BTS : `bts1.js` et `bts2.js` = **tronc commun** électrotechnique (modules avec `niveaux: ["BTS1-STI", "BTS1-ADM"]`) ;
`bts-sti.js` = option **STI** (conception : étude préliminaire, détaillée, réalisation) ; `bts-adm.js` = option **ADM** (analyse, diagnostic, maintenance).
Un module avec un seul niveau s'affiche chez l'élève sous « Option … », les autres sous « Tronc commun ».
**Ne renomme jamais l'`id` d'une fiche** déjà utilisée : le suivi des élèves y est rattaché.

## L'appli (installation sur le téléphone)

Rien à configurer : `manifest.webmanifest`, `sw.js` et `assets/appli.js` suffisent, une fois déposés sur GitHub.
- **iPhone** : dans Safari, bouton **Partager** → **« Sur l'écran d'accueil »**. L'appli a sa propre mémoire : l'élève s'y reconnecte une seule fois.
- **Android** : Chrome propose **« Installer »** (le tableau de bord de l'élève affiche aussi un bouton) ; sinon menu **⋮** → **« Installer l'application »**.
- **Toi** : depuis `prof.html`, la même manipulation installe « SI Papara prof », qui s'ouvre sur l'espace professeur.

Le site n'a pas besoin d'être fini : l'appli affiche le site en ligne. Le service worker va **d'abord au réseau** (les élèves ont toujours la dernière version déposée sur GitHub, `contenu/calendrier.js` compris) ; la copie gardée sur le téléphone ne sert que sans réseau. Les données (Supabase) ne passent jamais par lui. Quand la liste des scripts de `index.html` change, relancer `si_papara_appli.py` (il regénère `sw.js`).

## Signalements d'erreurs (à activer une fois)

Dans Supabase : **SQL Editor → New query**, colle tout `supabase/signalements.sql` → **Run**. Rien d'autre dans la base n'est touché (le même bloc est à la fin de `schema.sql` pour une installation neuve).
Tant que ce n'est pas fait, le bouton « Signaler une erreur » est visible mais les signalements ne partent pas, et l'onglet « Signalements » de `prof.html` rappelle la marche à suivre.
Un élève peut envoyer au plus 30 signalements par jour. « Copier le signalement » met tout (question, référence du générateur, réponses) dans le presse-papiers, prêt à transmettre pour faire corriger la question.

## Corriger une date (DS déplacé, semaine décalée) sans rien regénérer

Édite `contenu/calendrier.js` directement sur GitHub : deux lignes.
- `recalage: { "3": "2026-10-19" }` — la semaine 3 du plan commence le lundi 19 octobre ; toutes les semaines suivantes glissent d'autant, en sautant les vacances (le planning, « Cette semaine », les échéances des séries et les dates de cours suivent).
- `ds: { "DS 02": "2026-10-15" }` — le DS 02 change de jour sans décaler le reste ; les séries de ses notions sont à valider avant ce jour-là, 6 h.
Les numéros de semaine et les noms des DS sont ceux de « Tout le planning ». Quand le plan est regénéré (plan_src.py → si_papara_bac.py), remets `{ }` : les nouvelles dates sont alors dans les fichiers générés.

## Base en pause (plan gratuit de Supabase)

Sur le plan gratuit, Supabase met en pause une base restée 7 jours sans activité (pendant les vacances, par exemple) : plus personne ne peut se connecter (« Connexion refusée : Failed to fetch »). Pour la relancer : supabase.com/dashboard, le projet, **Resume project** ; les données reviennent telles quelles en quelques minutes.

Pour l'éviter, la tâche GitHub `.github/workflows/garder-base-active.yml` interroge la base tous les 3 jours (avec un jeton d'élève inconnu : rien n'est lu ni écrit). Si la base ne répond pas, la tâche échoue et GitHub envoie un e-mail. GitHub suspend les tâches planifiées d'un dépôt public resté 60 jours sans modification : après de longues vacances sans rien changer au site, la réactiver dans l'onglet Actions du dépôt.
